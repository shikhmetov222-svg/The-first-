# CAPITAL

Многопользовательский бизнес-симулятор в Telegram Mini App. Игрок открывает бизнесы, пополняет склады, ставит цены, торгует с другими игроками на рынке, улучшает бизнесы и соревнуется по капиталу в недельных сезонах.

Владелец проекта — не программист. Все технические решения принимает Claude; владельцу объясняем только ручные шаги, по одному и простыми словами, и после каждого этапа говорим, как проверить. Общение — по-русски.

## Стек

- **Клиент:** React 18 + Vite + TypeScript (`app/`). Иконки — `lucide-react@0.460.0`.
- **3D-улица:** three.js + `@react-three/fiber` 8 и `@react-three/drei` 9. Fiber 9 требует React 19, поэтому версия 8.
- **Сервер:** Supabase (проект `kadaesapsptfabygjkow`, eu-central-1):
  - Postgres — вся игровая логика в SQL-функциях plpgsql;
  - одна Edge Function `api` (`supabase/functions/api/index.ts`, `verify_jwt = false`, проверка — своя, по initData);
  - pg_cron:
    - `capital-tick` — каждые 5 минут;
    - `capital-hourly` — раз в час;
    - `capital-snapshot` — каждые 5 минут;
    - `market-maintenance` — каждые 5 минут;
    - `notify-dispatch` — рассылка уведомлений ботом, через pg_net.
- **Вход:** Telegram initData. Подпись проверяется на сервере (`supabase/functions/_shared/telegram.ts`).
- **Хостинг сайта:** GitHub Pages — https://shikhmetov222-svg.github.io/The-first-/. Сайт собирается сам при каждом push в `main` (`.github/workflows/pages.yml`). Netlify больше не используется: кончились бесплатные кредиты. `netlify.toml` остался от него.

## Выкладка

- **Сайт:** push в `main` → GitHub Pages. Vite собирает с `--base=/The-first-/`.
- **База:** новые файлы в `supabase/migrations/` (номер больше 0015) загружаются сами при push в `main` (`.github/workflows/db.yml`, секрет `SUPABASE_DB_URL`).
  - Каждый файл — одна транзакция.
  - Загруженные файлы записываются в `public.deploy_log`.
  - Миграции не меняем после загрузки — только новый файл со следующим номером.
- **Edge Function:** выкладывается через Supabase MCP `deploy_edge_function`. Передавать оба файла: `api/index.ts` и `_shared/telegram.ts`.
  - Если она вызывает новые SQL-функции — выкладывать после того, как миграция загрузилась (`deploy_log`).
  - Секреты (`TELEGRAM_BOT_TOKEN`, `ADMIN_TELEGRAM_IDS`) задаёт владелец в панели Supabase.
- **Supabase MCP:** без подтверждения можно только читать (`execute_sql` с select) — так проверяем результат. Изменения базы — только через миграции.
- Файлы `supabase/setup_*.sql` — старый ручной способ загрузки. Новых не создаём.

## Главные правила

### Вся логика — на сервере
- Клиенту не доверяем ни одно число. Клиент отправляет только действие и параметры; цены, деньги, склады, итоги считает сервер и возвращает новое состояние (`get_state`).
- Каждое действие — SQL-функция plpgsql:
  - с `set search_path = ''`;
  - с полными именами `public.…`;
  - переменные с префиксом `v_`, чтобы не путать с колонками.
- Каждая сделка и каждое действие разработчика — одна транзакция с блокировкой строк (`for update`). Порядок блокировок везде один: лот → игроки (по возрастанию id) → бизнесы.
- Ошибки правил игры — `raise exception 'Понятный текст'` (код P0001). Edge Function отдаёт их игроку как HTTP 400 с этим текстом.
- В конце каждой миграции:
  ```sql
  revoke execute on all functions in schema public from public, anon, authenticated;
  grant execute on all functions in schema public to service_role;
  ```
- RLS включён на всех таблицах без правил, права у anon и authenticated отозваны. Браузер в базу напрямую не ходит.
- **Деньги** хранятся в копейках (`bigint`), в интерфейсе выводятся в рублях.
- **Числа баланса** — в таблице `balance_config` (`cfg('ключ')`). Ключи `biz.<тип>.<поле>` и `market.<рынок>.<поле>` синхронизируются в справочники триггером. Новые числа баланса добавляем туда, а не в код.
- **Новая версия сервера не должна ломать старую базу и наоборот:** новые поля в клиенте — необязательные (`?`), новые параметры передаём только когда они нужны.
- **Рынок игроков:**
  - комиссия 5% сгорает;
  - защита от перекачки денег (кроме сделок администратора): не больше 3 покупок в сутки у одного продавца, пометки `friends`, `frequent`, `big_share`;
  - тестовые игроки торгуют только с администратором.
- **Сезон** длится 7 дней. В конце всё обнуляется: бизнесы, лоты, эффекты, деньги до стартового капитала.
- **Баланс** проверяем симуляцией (`supabase/sim/README.md`). Цель: окупаемость каждого бизнеса 2–4 дня при игре 2 раза в день, и ни один бизнес не выгоднее остальных.

### Режим разработчика
- **Администраторы** — только из секрета сервера `ADMIN_TELEGRAM_IDS`, никогда не из кода клиента.
- **Проверка на каждый вызов.** Действие разработчика заново проверяется на сервере по подписанному initData. Если ID нет в списке — отказ (`adminId()` в Edge Function).
- **Все действия — `dev_*`:** все функции разработчика называются `dev_*`, начинаются с `dev_lock_admin()` и пишут запись в `dev_log`.
- **Вкладка DEV** видна только администратору (`is_admin` приходит с сервера). В ней:
  - деньги и склады;
  - открытие бизнесов и уровни;
  - кампании, ремонты, посылки;
  - время (тики);
  - тестовые игроки и боты;
  - аналитика и журнал.
- **Счётчик FPS** на 3D-улице виден только администратору.
- **Тестовые игроки** не видны в рейтингах и не забирают покупателей у настоящих.

### Стиль интерфейса
- **Тёмная тема.** `--bg #0B0C0F`, карточки `--card #15171C`, рамки `--border #23262E`. Акцент — золото `#D4A73A`. Рост `--up #5FD39A`, падение `--down #F07167`, предупреждение `--warn #F2A65A`.
- **Шрифты:** Unbounded — заголовки и крупные числа, Manrope — текст.
- **Цвет никогда не единственный признак:** всегда со стрелкой ▲/▼ или словом («▼ −12% к рынку»).
- **Тексты:** по-русски, коротко, на «ты»; ошибки — понятными словами, что сделать. Суммы через `money()` («100 000 ₽»).
- **Мобильная вёрстка:** одна колонка под ширину телефона, кнопки не меньше 44 px. Действия — в нижних листах (`.sheet`), подтверждение — тостом и вибрацией Telegram (`feel()`, `notify()`).
- **3D-улица повторяет макет** `docs/street-mockup.html`:
  - геометрию не придумываем заново — меняем макет и перегенерируем `street/gen/`;
  - цвета как в r128: `ColorManagement` выключен, свет × π;
  - ночное освещение — только нарисованные свечения и пятна, без PointLight;
  - улица только показывает данные сервера и не меняет игру.

## Проверка перед выкладкой

- **Клиент:** `cd app && npx tsc -b && npm run build`.
- **SQL:** прогон на локальном Postgres 16 со всеми миграциями по порядку, затем ручные сценарии (`select …`) на тестовых игроках.
- **Edge Function:** проверка типов с подменой типов Deno.
- **Экран:** скриншоты через Playwright (Chromium уже установлен, `require('playwright')`). API Supabase и Telegram подменяются; для WebGL — флаги `--use-angle=swiftshader`.
- **После выкладки** — проверить живую базу только чтением: `deploy_log`, `cron.job_run_details`, `get_state` настоящего игрока.
